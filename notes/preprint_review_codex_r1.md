### 2. Claims that overreach

- **A scale threshold is not established.** “The failure labels split at 27B” ([line 320](/Users/xintianhuang/Research/wsp-scale-ladder/paper/preprint.md:320)) and “the failure modes change with size” ([abstract, line 20](/Users/xintianhuang/Research/wsp-scale-ladder/paper/preprint.md:20)) describe this sample, but two seeds per Qwen prompt and the strong early-stop/tool-use effects do not identify a threshold. Suggested wording: **“In these episodes, all four 27B runs met our localisation criterion, whereas none of the eight 0.8B/9B runs did.”**

- **The experiment does not show a smooth editor-size curve.** The sparse deepseek-flash model changes family, architecture, provider, and effective parameter count ([lines 13–14](/Users/xintianhuang/Research/wsp-scale-ladder/paper/preprint.md:13), [266–270](/Users/xintianhuang/Research/wsp-scale-ladder/paper/preprint.md:266)). Suggested wording: **“We compare three Qwen sizes and report deepseek-flash as a separate, cross-family point.”** The hinted and unhinted arms should remain separate.

- **The thinking-off control supports a shortcut diagnosis, but does not determine every cause of the score.** “A control settles where the score comes from” and “The edit buys the score by turning thinking off” ([lines 313–316](/Users/xintianhuang/Research/wsp-scale-ladder/paper/preprint.md:313)) are stronger than one stochastic control comparison. The decisive observation is that **473/500 edited outputs close thinking within 120 characters**, alongside the excluded-action rule. The 48.2% control is corroboration. Suggested wording: **“The edited model closes thinking almost immediately on most items. Its 51.8% score is close to the unedited model’s 48.2% with thinking disabled, consistent with the excluded shortcut.”** Also state that using the same per-item seeds did not make generation deterministic: [the phase-0 log](/Users/xintianhuang/Research/wsp-scale-ladder/notes/phase0_log.md) records **51.8% versus 47.6%** on a repeat of the edited checkpoint.

- **The frontier comparison has more than one changed condition.** “What separates the frontier reference” ([line 370](/Users/xintianhuang/Research/wsp-scale-ladder/paper/preprint.md:370)) invites a causal reading. Opus uses a different editor family and rules-v1-with-adjudication rather than strict2; only the hinted prompt is reported for Opus. Suggested wording: **“In the three hinted Opus reference episodes, the submitted edits preserved thinking on the early-close check and met the repair criterion. These episodes demonstrate feasibility under the audited reference protocol; they do not isolate editor scale as the cause of the gap.”**

- **Self-report errors are episode-dependent.** “The editors’ final answers misstate what they did at every size” ([abstract, line 22](/Users/xintianhuang/Research/wsp-scale-ladder/paper/preprint.md:22)) is supported only as “at least one episode at each size,” since several have zero material mismatches. Use that precise wording. Likewise, “the kind of error changes with size” ([line 451](/Users/xintianhuang/Research/wsp-scale-ladder/paper/preprint.md:451)) is a pattern in these few runs, not a demonstrated size effect.

### 3. Missing pieces, ranked

1. **An effort-controlled account of failures.** The 0.8B runs use zero forward passes, while many larger runs use dozens. A reviewer needs a compact table of early stops, tool-use failures, failed requests, and charged passes by cell, then a discussion of what can be attributed to diagnosis or editing once those differences are visible. The [run classifications](/Users/xintianhuang/Research/wsp-scale-ladder/notes/run_records/) already contain much of this.

2. **Uncertainty on the main comparisons.** Report per-cell success counts as **0/2**, score intervals or at least binomial uncertainty for one-sample MATH-500, and the repeat-score variability. Avoid inferential language about monotonicity or a 27B boundary. State exactly how “within sampling noise” ([line 294](/Users/xintianhuang/Research/wsp-scale-ladder/paper/preprint.md:294)) was calculated.

3. **Baselines that separate diagnosis, editing, and tool use.** The scripted, oracle-localisation floor is useful but not an end-to-end agent baseline. A fixed recipe with the same allowed data, a no-edit or random permissible edit baseline, and an explicit thinking-off control in the main results would make the task’s bar clearer. The absent fine-tuning baseline should be acknowledged as limiting claims about weight editing as a method.

4. **Operational definitions in the paper itself.** Define what counts as a saved edit versus a revert, a charged pass versus a failed request, a valid run after refused forbidden attempts, and a “repair” when an edit meets the numerical threshold but violates the task’s thinking requirement. The last point is particularly important for deepseek-flash hinted seed 1.

5. **Related work and reproducibility details.** Replace the citation placeholders, give model/checkpoint and evaluation versions, and state the harness deviations that affect comparability. [The phase-0 log](/Users/xintianhuang/Research/wsp-scale-ladder/notes/phase0_log.md) notes, for example, a **20 GB kernel cap versus the published prompt’s 96 GB**, notices moved to the start, and an independently constructed unhinted prompt.
