# How Small Can a Weight-Space Programmer Be?

Code, records and data for the preprint *How Small Can a Weight-Space Programmer Be?* (Xintian Huang, 2026;
[`paper/preprint.md`](paper/preprint.md), arXiv link to follow). The editors (Qwen 3.5 0.8B, 9B and 27B, deepseek-flash,
and Claude Opus 5.5 as a frontier reference) each try to repair the reasoning loops of a damaged Qwen3.5-0.8B through
its weights, under one protocol with a fixed forward-pass budget, a pre-execution rule reviewer and a post-hoc audit
of every tool call.

## What is where

| path | contents |
| --- | --- |
| `paper/` | the preprint (Markdown), its earlier section drafts, Figure 1 |
| `notes/analysis_plan.md` | the analysis plan with dated amendments A1–A8 |
| `notes/phase0_log.md` | the running lab log (decisions, incidents, fixes, with times) |
| `notes/episode_ledger.{md,json}` | one row per episode, generated by `scripts/ledger.py` |
| `notes/run_records/` | each run's classification, audit summary and adjudication; the truncation and thinking-off controls |
| `notes/note6_split_application.md`, `notes/pending_user_decisions.md` | rule rulings call by call, and when each was decided |
| `notes/astra_p50c_audit/` | our audit of the published GPT-6 Astra run |
| `notes/compute_log.md`, `notes/compute_split_2026-11-14.md` | compute and API spend |
| `scripts/` | task generation, episode launch, scoring, controls, audits, analyses, figures |
| `harness/` | OpenWiSH, vendored at upstream commit 4c369dc (`harness/UPSTREAM.md`) with our additions; its published runs are in `harness/results/` |

## Run data (release assets)

The episodes themselves are attached to the [v1.0 release](../../releases/tag/v1.0) as one `.tar.gz` per episode,
plus one per auxiliary folder (controls, conformance runs, the external audit, hold-out runs, reviewer calibration). Each
archive holds, relative to `harness/`: the rules and task spec, every turn's prompt, reply and raw API response, every
tool call with its output, forward-pass requests, the rule reviewer's decisions (`rule_gate.jsonl`), the audit
(`audit.jsonl`), the edit ledger with each edit's stated reason, the submitted edit (`final/editset/edit.npz`, the
changed tensors in full, and `manifest.json`), the scored outputs, and the classification files. Not included: full
model copies, intermediate edit tensors and sandbox scratch space. The GPQA hold-out records quote the questions,
which GPQA asks not to post in plain text, so they are in `gpqa_records.tar.gz.enc`, encrypted with the GPQA
dataset's own password: `openssl enc -d -aes-256-cbc -pbkdf2 -pass pass:deserted-untie-orchid -in
release/gpqa_records.tar.gz.enc | tar -xz -C harness`.

```sh
gh release download v1.0 -R lemonadesaltbagel/how-small-wsp -D release
python3 -I scripts/make_release.py verify release                 # archive hashes and member lists
for f in release/*.tar.gz; do tar -xzf "$f" -C harness; done      # plus the GPQA archive, see above
python3 -I scripts/make_release.py verify release harness         # every file against release/FILES.sha256
python3 -I scripts/ledger.py                                      # rebuilds notes/episode_ledger.{md,json}
python -I scripts/check_release_edits.py                          # each edit.npz against its manifest (numpy)
```

The target weights are not redistributed: the target is Qwen3.5-0.8B from Hugging Face, prepared by the harness's exp 8
task (`harness/tasks/`), and an edit is applied by replacing the tensors in `edit.npz`.
